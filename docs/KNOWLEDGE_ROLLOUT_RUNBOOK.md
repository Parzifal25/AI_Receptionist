## Inventory contract (future authorized read-only operation)

Produce tenant-separated counts, categories and reconciliation totals at a pinned schema/app revision and timestamp. Secure per-item reconciliation identifiers belong in approved restricted evidence, never customer content in repository reports. Global censuses are service-only administrative operations; normal tenant inventory must explicitly filter business_id on every source AND verify the parent tenant. Never join two untrusted identifiers without checking ownership.

| Inventory | Required categories beyond the built-in census |
|---|---|
| Documents / revisions | Total, no revisions, current draft/pending/published pointer, all review states, origin, content hash/provenance completeness; published pointer belongs to this document AND tenant; source/title/content bounds and empty/whitespace values |
| FAQs / revisions | Same tenant/parent checks, question/answer/category bounds, is_published mirror disagreement; no collection association exists for FAQs |
| Collections | Bound, unbound, missing/foreign collection, unknown configured collection, duplicate logical content hashes within tenant (report only); no cross-tenant deduplication |
| Chunks | Legacy null revision, missing document/revision parents, foreign tenant, wrong document for revision, duplicate revision/chunk_index, blank/malformed content, count versus expected, embedding missing/dimension mismatch |
| Indexing | Pending/indexing/ready/failed by revision, incomplete batches, error category only; ready is not approved and keyword-ready is not vector-ready |
| Approval | Submitter/reviewer/retirer and timestamps present where required, approver tenant role, stale publication versus replacement, drafts never auto-approved |
| Agent versions | Missing objective/identity/explicit language/effective instructions; unsupported retrieval policy, bad collection IDs, legacy published versions that fail activation; replacement through normal publication, no invented metadata |

`knowledge_governance_census(business_id)` returns eight named categories: documents_without_revision, faqs_without_revision, legacy_faqs_marked_published_but_unapproved, legacy_chunks_without_revision, chunks_with_foreign_document, documents_with_foreign_collection, empty_legacy_documents, revisions_pending_review. Its joins do not prove absence of orphan parents and it does not inventory every field above. Preserve all eight rows per tenant, including zeros; missing rows are NOT VERIFIED. The hosted preflight adds source_ref/category and serving/indexing counts but is still not the full inventory. Full orphan/duplicate/provenance checks require authorized operator queries reviewed against the actual schema. Do not mistake this specification for a completed census script.

## Verified draft indexing and retry method (no dashboard re-save)

Under separately authorized service-role indexing, first verify the exact business/document/revision triple and current state=draft; collection remains the original document association. A draft, including a legacy_backfill draft, may be indexed with knowledge_begin_indexing, revision-tagged chunk inserts, and knowledge_finish_indexing(expected_count), or the existing SupabaseKnowledgeProvider.indexRevision adapter with that exact triple. This changes indexing status/chunks, not content, provenance, revision ID or approval. Serialize per revision. Preserve any earlier published revision while preparing a different draft; never replace publication directly.

Only drafts may be indexed. Approved, pending-review, withdrawn or superseded revisions are refused; approved indexes are frozen. To change approved content/indexing, author a replacement through the normal governed revision path with explicit source metadata/collection, then index, submit and review. Never withdraw/re-save merely to resume indexing. No approval is inherited by a retry or replacement.

The disposable rehearsal first finishes an incomplete attempt (failed/unserved), restarts the same draft, inserts the complete expected chunks and reaches ready. It compares immutable revision identity/provenance/hash before/after, rejects a foreign tenant triple, and verifies approval remains draft until explicit owner review. It then verifies that reindexing an approved revision fails without changing approval and that keyword retrieval/scope remain correct. The independent production-provider DB test also covers the real indexRevision adapter with synthetic embeddings. No remote embedding provider is used. The existing begin RPC clears prior chunks for the selected draft; a crash after begin is recovered by that same serialized retry. Count/tenant/revision checks and readiness must pass before submit/review; partial chunks are never acceptance.
